# Spice.ai .NET SDK v0.5.0 Release Notes

## New Features

### Runtime Status

New `SpiceClient.GetRuntimeStatusAsync(CancellationToken)` wraps the runtime's `GET /v1/status` endpoint. It returns one `ConnectionDetails` (`Name`, `Endpoint`, `Status`, `StatusText`) for each network-facing component of the runtime: `http`, `flight`, `metrics` and `opentelemetry`. `IsSpiceReadyAsync` gives only one `true` or `false`. `GetRuntimeStatusAsync` tells you which component is not ready. ([#31](https://github.com/spiceai/spice-dotnet/pull/31))

```csharp
using Spice;

using var client = new SpiceClientBuilder().Build();

foreach (var component in await client.GetRuntimeStatusAsync())
{
    Console.WriteLine($"{component.Name,-14} {component.Endpoint,-18} {component.Status}");
}
```

- `Status` is a `ComponentStatus`: `Initializing`, `Ready`, `Disabled`, `Error`, `Refreshing`, `ShuttingDown` or `NotLoaded`. A state that this SDK version does not know is `Unknown`, and `StatusText` keeps the value that the runtime sent.
- When the runtime is not reachable, `GetRuntimeStatusAsync` throws `HttpRequestException`. This is different from `IsSpiceReadyAsync`, which returns `false`.
- A response that is not a list of `{name, endpoint, status}` strings throws `JsonException`. The error identifies the entry and the field.

With this release, all six Spice SDKs support `/v1/status`.

## Fixes

### `grpc://` Flight Addresses

`WithFlightAddress("grpc://my-server:50051")` now works. Before, `Build()` threw `InvalidOperationException`, also for the example in the README. ([#30](https://github.com/spiceai/spice-dotnet/pull/30))

| Address scheme | Connects with |
|---|---|
| `grpc://`, `grpc+tcp://`, `http://` | Plaintext |
| `grpc+tls://`, `https://` | TLS |
| No scheme | Plaintext, or TLS when you call `WithTls()` |

These rules also apply to an address from `SPICE_LOCAL_FLIGHT_URL`.

### Fewer Restrictions on the API Key Field for Self-Managed Runtimes

`WithApiKey` now has fewer restrictions on the API key value. Before, the key had to use the Spice Cloud format `appId|secret`, and other values threw `apiKey must be in format 'appId|key'`. Now the client accepts any value that is not empty. Thus you can connect to a self-managed Spice runtime that has [API key authentication](https://spiceai.org/docs/api/auth) enabled. ([#30](https://github.com/spiceai/spice-dotnet/pull/30))

```csharp
using var client = new SpiceClientBuilder()
    .WithFlightAddress("grpc://localhost:50051")
    .WithHttpAddress("http://localhost:8090")
    .WithApiKey("my-runtime-key")
    .Build();
```

- When you send the key to a self-managed Spice runtime (an address that is not Spice Cloud), or when the key does not use the `appId|secret` format, the key goes out as `Authorization: Bearer <key>` on each Flight call and each parameterized (ADBC) query, with no handshake. HTTP calls send `X-API-Key`.
- A Spice Cloud key (`appId|secret`) that you send to Spice Cloud continues to use the Basic handshake and session token.

## Behavior Changes

- **A Flight address with an unsupported scheme throws in `WithFlightAddress`.** An address with a scheme that is not in the table above, or without a valid host, now throws `ArgumentException` when you set it. Before, the error came later, from `Build()`. ([#30](https://github.com/spiceai/spice-dotnet/pull/30))
- **The HTTP client does not follow redirects when it sends `X-API-Key`.** A redirect to a different origin would send the API key to that origin. ([#30](https://github.com/spiceai/spice-dotnet/pull/30))
- **`WithSpiceCloud` error message.** `WithSpiceCloud` continues to require an `appId|key` key. Its error message now says so. ([#30](https://github.com/spiceai/spice-dotnet/pull/30))
